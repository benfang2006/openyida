# 场景：工作台 / 门户首页

> 用户进入应用的第一屏，「看一眼状态 + 快速跳去干活」。不是营销落地页，不要大 Hero 图套路。

## 场景定位

- **用户目标**：进来 3 秒内知道「有什么要我处理的 / 关键数据怎么样 / 我常用的入口在哪」。
- **不是**：品牌展示页、数据大屏（那是 dashboard）、某个对象的详情（那是 detail）。
- **典型业务**：部门门户、系统首页、我的工作台、班组看板首页。

## 页面布局和入口关系

自上而下的纵向叙事（移动优先）：

```
┌─────────────────────────────────────┐
│ 欢迎区（问候 + 当前用户 + 日期/待办数）│  ← 克制，1 行 2 行，不做大图 banner
├─────────────────────────────────────┤
│ 状态摘要（1 主 + 2-4 辅，紧凑条）      │  ← 门户级概览，不是完整看板，不铺大 KPI 卡
├─────────────────────────────────────┤
│ 快捷入口（分组，有主次）              │  ← 高频操作在前，长尾折叠/靠后
├─────────────────────────────────────┤
│ 我的待办 / 最近动态                    │  ← 列表，可点进详情
└─────────────────────────────────────┘
```

PC 端可将「状态摘要 + 高频动作」并成上区、「待办 + 动态」并成下区双栏，右侧放最近记录、提醒或上下文面板；移动端全部纵向堆叠。默认不要用 4 张等宽大卡片撑满首屏。

工作台页面至少规划 10 个有业务目的的区块以上。推荐拆法：克制标题区、当前用户/日期上下文、主状态摘要、辅助状态组、高频动作组、待办列表、最近记录、业务动态、提醒/异常、右侧上下文、空态行动或底部辅助信息。区块可以紧凑排列，不能为了凑数增加重复大卡片。计数按区块组算：4 个 KPI 子项仍然只是 1 个状态摘要区块，4 个快捷入口仍然只是 1 个动作区块。

## contentBlocks 槽位

1. 标题上下文：应用名、角色、当前周期或当前门店/班级/项目。
2. 用户与日期：当前处理人、日期、班次、部门或角色视角。
3. 筛选上下文：门店、班级、项目、周期、状态或责任人。
4. 主状态摘要：最重要的 1 个状态判断。
5. 辅助状态组：2-4 个紧凑指标，不能做等高大卡。
6. 高频动作条：当前页动作、表单新建、查看记录或刷新。
7. 待处理列表：真正承接下一步工作。
8. 最近记录：最近成绩、最近入库、最近工单、最近客户等业务记录。
9. 业务动态流：按时间展示变化。
10. 提醒/异常：风险、逾期、低库存、缺资料、待确认。
11. 右侧上下文：负责人、分组、目标、说明、常用链接或洞察。
12. 空态行动：无数据时的登记、发布、刷新、补录或配置入口。

## 源码 primitive

- `rootShell`：平台导航内浅底业务页；隐藏导航时才使用页面内导航壳。
- `prioritySurface`：待处理列表、主任务区或主状态摘要，不是欢迎语。
- `statusPrimitive`：72-96px 紧凑状态摘要条或侧栏小面板。
- `actionPrimitive`：44-64px 高频动作条，表单提交入口默认隐藏导航。
- `contentPrimitive`：任务列表、最近记录、动态流至少出现其一。
- `contextPrimitive`：右侧提醒、负责人、业务说明或下一步建议。
- `statePrimitive`：薄空态行 + 登记/刷新/补录动作。
- `responsiveRule`：移动端按标题、状态、动作、待办、记录、上下文顺序堆叠。

## 信息密度

**中**。门户是概览不是明细——每块只放最重要的，深入靠点击跳转。留白要够，别把首页做成信息轰炸。

## 焦点（hero）元素

**待处理事项 + 主快捷入口 + 紧凑状态摘要**。欢迎区是配角，不要让问候语、装饰图或大 KPI 卡占掉首屏焦点。

## 组件套餐（映射 design-system.md / component-jsx-guide.md）

- 状态摘要：紧凑指标条 / 分段摘要 / 小型趋势点，数字使用 `tabular-nums`，只突出 1 个主指标
- 快捷入口：图标 + 文字的入口块（图标此处是功能性导航，允许，但风格统一）
- 待办/动态：`design-system.md` 数据列表行（listItem）
- 空态：`design-system.md` 空状态（新用户无待办时友好提示 + 主操作）

快捷入口目标如果是同应用内页面，优先把目标放进平台应用导航或导航分组，由导航内切换；工作台内容区不要再铺一组“跳到应用内其他页面”的入口卡。内容区快捷入口保留给当前页动作、表单新建/查看、外部链接、跨应用资源，或用户显式隐藏平台导航后的页面内导航壳。

## 本场景专属去 AI 味要点

- ❌ **禁营销大 Hero**：不要顶部一张巨图 + 渐变遮罩 + 大标语。B 端门户不是官网。
- ❌ **禁四张大 KPI 白卡撑首屏**：不要“标题 + 4 个等宽大卡片 + 彩色图标 + 大数字 0”。工作台不是低密看板，统计为 0 时更不能占用大面积。
- ❌ **禁大空态白卡**：没有宠物/动态/活动时，不要铺 200px 高空白卡片；改成薄空态行、说明文字和明确登记/发布按钮。
- ❌ **禁快捷入口平铺一片等宽图标格子**：入口要分组、有主次（高频 vs 低频），不是 4×N 的对称九宫格。
- ❌ **禁把同应用页面全做成快捷入口卡**：应用内页面跳转优先放入平台导航，页面内容区只放真正要在首页触发的动作。
- ✅ **欢迎区克制**：一句问候 + 关键数字（如「今天有 3 项待办」）即可，别配大插画和 emoji。
- ✅ **摘要有主次**：最重要的 1 个状态可放在视觉起点，其余压缩成小指标、标签或列表字段，不要 4-5 个 KPI 一样大平铺。
- ✅ **优先任务结构**：首屏至少出现一个任务/动态/最近记录、可处理列表或右侧上下文面板；如果没有数据，用真实空态行动替代大卡片占位。

## PRD 场景片段示例

```markdown
### 【PRD 写入】
- 页面类型：workbench（用户诉求是"部门门户首页，进来先看待办和常用功能"）
- 气质关键词：稳重、高效、克制
- 项目特定原则：① 待办数量必须首屏可见；② 高频入口（提交申请/查进度）永远在入口区最前；③ 指标只放部门最关心的 3 个
- 布局骨架：欢迎区(1 行) → 紧凑状态摘要(1 主 + 2 辅) → 高频动作(分组) → 我的待办/最近动态列表
- 信息密度：中（概览为主，深入靠跳转）
- 视觉焦点：核心指标 + 主快捷入口

### 【差异化 5 维】
1. 辅助/强调色：待办数用点缀色强调，逾期用告警红（仅此处）
2. 中性冷暖偏色：冷灰基底（政企门户，专业感）
3. 圆角性格：微圆（克制企业感，全页统一）
4. 排版性格：指标数字大字 + tabular-nums；标题 600 正文 400
5. 装饰母题：重点待办左侧主色竖条 + 单色阶分区（不用彩色卡片区分）

### 【反默认说明】
用冷灰基底 + 微圆 + 单色阶分区替代「灰白底 + 四张大 KPI 白卡 + 彩色图标网格」，且快捷入口分组而非九宫格平铺——3 维偏离默认脸。

### 【图标策略】
内联 SVG 语义集，细描边；仅快捷入口和状态用图标，标题不配装饰图标。
```
