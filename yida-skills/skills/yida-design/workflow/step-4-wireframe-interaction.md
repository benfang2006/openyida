# Step 4：页面原型与交互

> 低保真不追求好看，先把结构、区块和操作路径定清楚。

## 页面布局

- 工作台：欢迎/状态摘要 + 高频入口 + 待办动态 + 数据概览。
- 列表页：筛选区 + 工具栏 + 表格/卡片 + 分页 + 详情抽屉。
- 详情页：对象 Hero + 摘要指标 + 分区信息 + 时间线/关联对象。
- 看板页：KPI 卡组 + 图表组 + 排行/明细 + 刷新时间。
- 大屏页：中心态势 + 左右信息塔 + 告警/趋势 + 投屏可读层级。
- 官网页：首屏主张 + 产品/服务 + 过程/案例 + 信任背书 + CTA。

## 内容区块

每个区块写清：

- 区块目的：让用户判断、进入、处理、查看还是转化。
- 关键字段：来自哪个表单/流程/报表。
- 主操作：按钮、行点击、抽屉、跳转或原生表单入口。
- 状态：空态、加载、错误、无权限、无数据。

## 交互路径

- 列表下钻默认保留上下文，PC 用详情抽屉或主从分栏。
- 新增/提交页 URL 仍使用原始 `submission/{formUuid}`；PC 抽屉 iframe 承载，移动端整页或新页打开。
- 数据列表嵌入用 `workbench/{formUuid}?iframe=true`。
- 页面美感提升/改 UI 时，按钮动作、筛选逻辑、下钻目标、数据源、字段映射、提交 URL、权限和业务状态保持当前功能契约；布局调整只改变呈现位置和视觉层级。
- 需要页面内导航壳时，先确认是否真的隐藏平台导航；隐藏后再交给 `yida-nav-shell`。

## 产出

```markdown
- 布局骨架：<上下/左右/卡片流/列表/主从/大屏>
- 内容区块：<区块列表 + 目的>
- 主操作：<入口、按钮、下钻、提交、返回>
- 功能契约：<保留的数据源/字段映射/按钮动作/筛选逻辑/提交 URL/权限/状态>
- 响应式策略：<PC / 移动端差异>
- 原生表单入口：<新增/提交/编辑打开方式>
```
