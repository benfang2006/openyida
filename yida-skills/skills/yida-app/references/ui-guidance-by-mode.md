# yida-app UI 引导分层

完整应用搭建时，UI 引导按模式分层。目标是让 `fast_build` 足够轻、能直接交付；让 `full_demo` 和 `deep_design` 有更完整的体验规划，但不把这些动作提前塞进 fast。

## 共同产物

无论哪种模式，主页面实现前都要形成可写入 `page-spec.json` 的结构化决策：

| 字段 | 说明 |
| --- | --- |
| `uiGuidanceLevel` | `fast` / `demo` / `deep` |
| `pageType` / `template` | 页面类型和 `generate-page` 模板 |
| `navPolicy` | 使用平台导航、页面内导航壳或混合导航 |
| `quickEntryPolicy` | 应用内入口走导航内切换；外部链接才新开 |
| `visualProfile` | 信息密度、构图节奏、强调色来源、列表/图表/队列母题 |
| `interactionProfile` | 主操作、下钻方式、批量动作、空/载/错状态 |
| `dataBinding` | 真实表单/连接器/空态策略 |

## fast_build：轻量但明确

适用：用户要求默认方案、不要追问、直接创建、尽快搭建。

执行口径：

- 只做一次 `yida-page-uiux` 轻量引导，输出 6-8 行决策块，不做长 PRD、不加载 `yida-app-uiux`。
- 默认导航可见，主色默认从基础 token preset `blue`、`green`、`orange` 三选一；只有用户明确要求应用主题风格/应用主题色时才跟随 `yida-app-theme`。只有用户明确要求隐藏平台导航、无导航全屏大屏、独立门户壳或生成器已选择自绘导航壳时，才隐藏应用导航。
- 快捷入口先分成 `page/app/submission/detail/url`。`page/app` 指向应用内导航路径，`url` 才新开。
- 主页面只实现 MVP 首屏、核心入口、真实空态和必要指标；没有真实记录时展示登记入口、刷新按钮和数据接入提示。
- 不默认执行导航整理、示例数据、截图验收、公开访问、深度主题设计或多页面蓝图。

fast 决策块示例：

```markdown
### 【视觉方向决策】
- uiGuidanceLevel: fast
- 导航形态: 导航可见，跟随应用主题
- 页面类型: workbench，模板 workbench-home
- quickEntryPolicy: 应用内页面走 /{appType}/workbench/{formUuid} 导航内切换；外部链接才新开
- visualProfile: 中密度业务工作台，左侧状态摘要 + 中部快捷入口 + 右侧待办动态
- dataBinding: 已有客户表单则 mode=form；无记录时展示空态和新增入口
```

## full_demo：可演示体验加固

适用：用户明确要演示、可点验收、示例数据、导航整理或截图。

在 `fast_build` 发布成功后按需追加：

- 整理平台导航顺序，让主页面、核心表单、报表/配置入口顺序符合业务路径。
- 写入少量示例数据并 query 抽查，再让 Canvas 读取真实表单记录；页面不得用前端 seedRows 冒充真实业务。
- 补一条可演示点击路径：入口点击、列表筛选、详情下钻、空态/错误态恢复。
- 有截图能力时做 PC/移动端截图验收；不能截图时明确缺口。

## deep_design：产品体验蓝图

适用：用户明确要求深度产品设计、复杂多角色、多页面体验、品牌化视觉、应用级导航蓝图。

执行口径：

- 先加载 `yida-app-uiux` 做应用体验蓝图：角色、页面组合、导航分组、主入口、页面关系。
- 再加载 `yida-page-uiux` 做当前页面的完整视觉方向：导航形态、页面类型、差异化 5 维、素材/图标策略、去 AI 味自检。
- 涉及全局品牌或应用主题时加载 `yida-theme`；涉及隐藏导航时叠加 `yida-nav-shell`。
- 可以先停在 PRD/蓝图确认点；只有确认后再进入资源创建和页面发布。

## 升级触发

`fast_build` 只在出现以下信号时升级：

- 用户明确说“深度设计 / 多角色 / 多页面蓝图 / 先出方案 / 视觉体系 / 品牌化全局主题”。
- 用户要求可演示数据、导航整理、公开访问或截图验收，升级到 `full_demo` 后置。
- 页面必须隐藏应用导航并自建多级导航壳，且顶级模块超过 3 个，至少进入完整 `yida-page-uiux` 决策。

不要因为应用名包含“系统、管理、看板”就自动升级。普通 CRM、订单、客户、项目、访客等默认仍是 fast。
