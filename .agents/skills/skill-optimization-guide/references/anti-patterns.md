# 反模式速查

## 用途

步骤 4 验证时，逐条对照检查改写后的文件有没有踩坑。

## 反模式列表

| 错误做法 | 正确做法 | 怎么判断踩了坑 |
|---------|---------|--------------|
| SKILL.md 里贴完整代码 | 入口零代码，完整实现放 references 或 assets | SKILL.md 里有超过 5 行的代码块 |
| 同一条规则在 2+ 个文件里都详细解释 | 入口写一句话摘要，详细解释只放一处 | grep 发现同一段话出现两次 |
| 用抽象词描述（胶水/赋能/闭环） | 列出具体的入口、组件、操作和结果 | 读完这句话后不知道具体要写什么代码 |
| 规则以"不要/禁止/避免"开头（非高风险） | 改成正向写法："PC 端用抽屉打开" | 只说了不能做什么，没说应该做什么 |
| 入口声称 N 条规则但实际展开数量不同 | 严格对齐，入口写几条 references 就展开几条 | 数一数发现数量不等 |
| 小于 50 行的内容单独建文件 | 合并到最相关的文件中 | 打开一个 .md 文件发现内容只有一两段 |
| references 里放完整可运行代码 | 只放骨架（函数签名 + 注释），完整代码放 assets 或源码 | reference 文件可以直接复制粘贴运行 |
| 相关文件列表缺少文件 | references/ 下每个文件都要出现在列表里 | ls references/ 的结果和列表对不上 |
| 相对路径写错层级 | 从当前文件位置算正确的相对路径 | 点击链接 404 |
| 写"后续可以再拆" / "临时方案" | 删除未来规划，只写当前执行规则 | 出现"后续/临时/暂时/可以再"等词 |
| 写"这个设计是为了避免..." | 删除原因解释，只写最终结论 | 出现"为了/因为/所以"的解释段落 |
| script 和 assets 混在一起 | 可运行脚本放 script/，模板素材放 assets/ | script/ 里有 .json 模板，或 assets/ 里有 .sh 脚本 |

## 自查口诀

改写完每个文件后问自己三个问题：

1. **agent 读完这句话，能直接动手吗？** — 不能就改成具体动作。
2. **这句话在别的文件里也写了吗？** — 写了就删一处。
3. **这句话是在说"不要做什么"吗？** — 是的话改成"应该做什么"。
