# 步骤 3：逐文件改写

## 输入

- 步骤 2 产出的新文件清单
- [写作规则](../references/writing-rules.md)

## 操作

按新文件清单，逐个文件改写。每个文件改写时遵循以下顺序：

### 3.1 改写 SKILL.md

SKILL.md 的章节按需组合，以下是可选章节池（按出现顺序排列）：

```
---
name / description（frontmatter，必须有）
---
# 标题 + 一句话定位（必须有）
## 作用域 / 入口路由（必须有：判定表格，区分本 skill 处理什么、不处理什么）
## 铁律 / 严禁事项（按需：高风险红线，3-7 条）
## 流程 / 流程概览（必须有：两种写法二选一）
## 技能协作 / 子技能集成（按需：和其他 skill 的依赖关系）
## 核心规则（必须有：正向引导的执行规则）
## Checklist（按需：完成自检项）
## 参考文件（必须有：列出 references/ 和其他相关文件）
```

章节名称可以根据 skill 的语境选择最直白的表达（比如"铁律"比"严禁事项"更直白，"入口快速路由"比"作用域"在复杂路由场景更清晰）。

---

**流程有两种写法，按复杂度选：**

#### 写法 A：简单流程（直接写在 SKILL.md 里）

适用于步骤少、每步可以在 SKILL.md 里直接写清楚的 skill。不需要 workflow/ 目录。

```markdown
## 工作流程

### 第一步：需求收集

收到用户输入后，执行以下判断：
- 条件 A → 动作 A
- 条件 B → 动作 B

处理规则：
- xxx
- xxx

### 第二步：产品设计

此环节由 `xxx` 技能负责。需向设计环节提供以下信息：
- xxx
- xxx

### 第三步：开发

...
```

#### 写法 B：复杂流程（拆到 workflow/ 目录）

适用于步骤多（>4 步）或单步内容长（>50 行）的 skill。SKILL.md 里只放概览表格。

```markdown
## 流程概览

> 📌 仅当判定为「全量搭建」时进入此流程。

| 步骤 | 名称 | 功能描述 | 产出物 |
|------|------|----------|--------|
| 1 | [需求解析](workflow/step-1-requirement.md) | 解析需求、采集品牌信息 | 需求总结 |
| 2 | [产品设计](workflow/step-2-product-design.md) | 落地视觉设计与页面结构 | SPEC.md |
| 3 | [前端开发](workflow/step-4-frontend.md) | 构建前端页面，完成后先部署预览 | 前端代码 + 预览地址 |
```

**怎么选：** 所有步骤内容加起来不超过 150 行，用写法 A；超过了用写法 B。

---

**铁律/严禁事项的写法标准：**

- 只放真正的高风险操作（数据丢失、权限越界、发布错误、流程中断）
- 格式：加粗标题 + 冒号 + 具体约束说明
- 数量控制在 3-7 条
- 可以包含条件判断逻辑（如"除非 xxx，否则必须 xxx"）

---

### 3.2 改写 workflow 文件（仅写法 B 需要）

每个 step 文件结构：

```
# 步骤 N：动作名
## 输入
## 操作（编号列表，每步一个动作）
## 产出
## Checklist
```

### 3.3 改写 references 文件

每个 reference 文件结构：

```
# 标题
## 用途（一句话说明什么时候查这个文件）
## 正文（表格、编号列表、骨架代码）
```

### 3.4 每句话的改写标准

| 改写前（不合格） | 改写后（合格） | 原因 |
|----------------|--------------|------|
| "自定义页负责胶水" | "自定义页放置表单提交入口、流程入口、报表入口" | 去掉抽象词，列出具体东西 |
| "不要在 PC 端 window.open" | "PC 端用抽屉 iframe 打开，移动端整页打开" | 正向写法，告诉做什么 |
| "这个设计是为了避免..." | 删除，或移到 docs | skill 不写原因 |
| "如果后续发现过大可以再拆" | 删除 | skill 不写未来规划 |

## 产出

改写后的全部文件。

## Checklist

- [ ] SKILL.md 建议 300 行以内
- [ ] SKILL.md 必须包含：作用域、流程、核心规则、参考文件
- [ ] SKILL.md 按需包含：铁律/严禁事项、技能协作、Checklist
- [ ] 流程格式已按复杂度选择（简单 → 写法 A 内联；复杂 → 写法 B 拆目录）
- [ ] 如果用写法 B，每个步骤都有链接指向 workflow 文件
- [ ] 如果用写法 B，每个 workflow 文件都有输入、操作、产出、Checklist
- [ ] 铁律/严禁事项只有 3-7 条，都是真正的高风险操作
- [ ] 每句话都能回答"agent 拿到这句话后具体做什么"
- [ ] 无抽象词（胶水/赋能/闭环/中台/一体化）
- [ ] 正向写法为主，"禁止"只出现在铁律/严禁事项章节
