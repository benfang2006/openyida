# 步骤 2：拆分重组

## 输入

- 步骤 1 产出的问题清单
- [目录规范](../references/directory-convention.md)

## 操作

根据问题清单，规划新的文件结构：

1. **确定文件清单**：列出优化后需要哪些文件。
2. **分配内容**：每条信息只放一个文件，按下表判断放哪里：

| 这条信息是什么 | 放哪里 |
|--------------|--------|
| 触发条件、作用域、流程总览、完成标准 | SKILL.md |
| 超过 4 步的顺序操作 | workflow/step-*.md |
| 规则的详细解释、参数表、场景列表 | references/*.md |
| 可复用的模板、脚本、素材 | assets/ |

3. **处理重复**：问题清单中标记的每处重复，决定保留在哪个文件，其他文件删除或改为一句话引用。
4. **处理小文件**：内容少于 50 行的独立文件，合并到最相关的文件中。

## 产出

新文件清单，格式如下：

```markdown
## 新文件结构

| 文件 | 放什么内容 | 预估行数 |
|------|-----------|---------|
| SKILL.md | 触发、流程表、规则摘要（5条）、完成标准、导航表 | ~70 行 |
| workflow/step-1-xxx.md | ... | ~40 行 |
| references/xxx.md | ... | ~60 行 |
```

## Checklist

- [ ] 每条信息只分配给了一个文件
- [ ] 问题清单中的每处重复都明确了保留位置和删除位置
- [ ] 少于 50 行的小文件已合并
- [ ] SKILL.md 预估不超过 80 行
- [ ] 目录结构符合目录规范
